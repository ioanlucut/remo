How the loop works

Every packet is a real request. Click a network link to cut it.

  1. Read. The controller asks the remote sensor for the process value, with a timeout shorter than one sample.
  2. Compute. The PID turns the error into an output. Gains are per second, so tuning survives a change of sample rate.
  3. Actuate. The output goes to the remote actuator, whose watchdog closes the valve if commands stop.
  4. Respond. The process follows the valve with a gain, a lag and a dead time, and the sensor measures it.

Try this

  • Cut the sensor link. The controller holds its output, then goes fail-safe after 3 s, and resumes without a bump.
  • Cut the actuator link. The integrator freezes, and the actuator's own watchdog closes the valve after 1 s.
  • Add 60 ms latency. Answers now arrive after the 40 ms timeout, so a slow link counts as a lost one.
  • Raise the dead time to 4 s. The same gains now oscillate. Retune to Kp 1 and Ki 0.1 to settle it.
